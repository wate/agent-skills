引き継ぎ資料の項目別記述例
==========================

このドキュメントは、テンプレートの各項目に何を書くかを短い例で示します。
テンプレート本体は[../assets/template.md](../assets/template.md)を参照してください。

目的
-------------------------

```markdown
案件管理機能のMVPを完成させ、案件登録から検索までの基本導線を1人で運用できる状態にする。
```

背景
-------------------------

```markdown
案件情報が複数ツールに分散しており、過去案件の参照に時間がかかっている。
次セッションでは「検索条件の優先順位」を決める必要があるため、業務上の利用頻度を基準に判断する。
```

未決事項
-------------------------

```markdown
- [対応中] 一覧画面のデフォルト並び順: 更新日順と作成日順のどちらを採用するか未決
- [対応中] ステータス定義の粒度: 区分数を3または4で検討中
- [確認待ち] CSV取込の必須項目: 運用担当の回答待ち（回答期限: 2026-04-25）
```

決定事項
-------------------------

```markdown
- [2026-04-23] 一覧画面のデフォルト並び順: 更新日降順で確定
    - 理由: 直近案件の参照頻度が高い
    - 影響範囲: 一覧画面、検索結果表示
    - 根拠: docs/requirements.md
- [2026-04-23] ステータス定義: 「進行中/保留/完了」の3区分で確定
    - 理由: 運用現場の報告粒度と一致
    - 影響範囲: 一覧フィルタ、集計
    - 根拠: docs/schema/cases.md
- [2026-04-23] 【移管】ステータス定義の粒度: 区分数を3または4で検討中 -> 「進行中/保留/完了」の3区分で確定
    - 理由: 4区分案は誤分類が増えた
    - 影響範囲: 入力フォーム、集計
    - 根拠: docs/requirements.md
- [2026-04-24] 【更新】検索入力UI: ~~自由入力中心~~ -> 選択式中心へ変更
    - 理由: 入力ゆらぎと誤記の抑制
    - 影響範囲: 検索フォーム、CSV取込
    - 根拠: docs/requirements.md
```

課題とリスク
-------------------------

```markdown
- 【課題】[対応中] 検索条件が増えすぎてUIが煩雑: フィルタを基本/詳細に分離する案で検証中
- ~~【課題】[対応中] 一覧描画が遅い~~ -> [解決済み: 2026-04-23] インデックス追加で応答時間を改善
- 【リスク: 中】[対応中] 権限設計が遅れると画面改修が再発する可能性
- ~~【リスク: 高】[対応中] バックアップ手順未整備~~ -> [解消済み: 2026-04-22] 自動バックアップ手順を運用手順書へ追加
```

タスク一覧
-------------------------

```markdown
1. [x] フェーズ1: 要件レビューと設計前提の固定 【状態: 完了】【進捗: 100%】
    - 実施内容: 要件とペルソナの見直し、MVP範囲確定
    - 残り作業: なし
2. [ ] フェーズ2: 業務プロセスとデータ構造の整理 【状態: 進行中】【進捗: 60%】
    - 実施内容: 主要エンティティ整理とDBたたき台作成
    - 残り作業: 画面遷移と一覧項目の最終確定
3. [ ] フェーズ3-A: 認証/認可とルーティング方針の確定 【状態: 次アクション】【進捗: 20%】
    - 実施内容: 一部の選択肢比較まで実施
    - 残り作業: 方針決定と根拠の記録
4. [ ] フェーズ4: 実装着手 【状態: 保留】【進捗: 10%】
    - 実施内容: 実装チケットの下書き作成
    - 残り作業: フェーズ2-3確定後に着手
```

完了条件
-------------------------

```markdown
1. 案件の登録/編集/一覧/検索が仕様どおりに動作する
2. 権限別に表示と操作制御が適用されている
3. 主要シナリオの確認結果を作業ログに記録済みである
```

指摘事項
-------------------------

```markdown
- テスト観点が不足しやすいので、UI確認だけで完了扱いにしない
- 仕様変更時は先に背景と影響範囲を更新してから実装する
```

作業ログ
-------------------------

```markdown
### セッション3 (2026-04-23)

- 実施内容:
    - `docs/requirements.md`: 検索条件を必須3項目と詳細条件へ分離、一覧のデフォルト並び順を追記
    - `docs/schema/cases.md`: ステータスを3区分へ変更、一覧クエリ用のインデックス定義を追加
    - 調査: 権限設計の方式を比較し、ロールベースと属性ベースの2案へ絞り込み
- 完了タスク: 2. 業務プロセスとデータ構造の整理, 5. 一覧クエリの改善
- 設計判断サマリ:
    - 検索条件を必須3項目と詳細条件へ分離: 条件数の増加で入力欄が煩雑になったため
    - 画面制御の最終決定を保留: 権限設計が未確定で手戻りが発生するため
```

実施内容は「`ファイルパス`: 変更内容」の1行形式にします。
作成・修正ファイルの一覧は成果物セクションが持つため、作業ログには記載しません。

次は避けるべき記述例です。操作単位への分解、ファイルパスの重複列挙、試行錯誤の記録により肥大化しています。

```markdown
### セッション3 (2026-04-23)

- 実施内容:
    - docs/requirements.mdを読み込み、現在の検索条件の記述を確認した
    - 検索条件が7項目あることが判明したため、分離方針を検討した
    - 4項目と3項目へ分ける案を試したが、入力欄が収まらなかった
    - docs/requirements.mdへ必須3項目の記述を追加した
    - docs/requirements.mdへ詳細条件の記述を追加した
    - docs/requirements.mdへ並び順の記述を追加した
    - docs/schema/cases.mdのステータス定義を確認した
    - docs/schema/cases.mdのステータスを3区分へ変更した
- 完了タスク:
    - [x] フェーズ2の「エンティティ整理」【状態: 完了】【進捗: 100%】
    - [x] 一覧クエリの改善【状態: 完了】【進捗: 100%】
- 作成・修正ファイル:
    - docs/requirements.md
    - docs/schema/cases.md
```

今後の検討事項
-------------------------

```markdown
- 複数案件の一括編集: 選択肢比較未実施（優先度: 中、後続MVPで検討）
- CSV一括削除: 危険性の検証が必要（優先度: 低、運用ガイドラインと並行検討）
- 権限設計の全体検討: 現在は管理者/ユーザーの2層だが、チームごとのアクセス制限の検討が必要（優先度: 中、以降のセッションで優先度判定）
- 監査ログの記録: セキュリティポリシー内で検討予定（優先度: 高、次セッションで実装判断）
```

記述時の最小ルール
-------------------------

```markdown
- 過去の判断は削除せず、未決事項から決定事項へ移管して履歴を残す
- タスク順序は維持し、チェックボックスと状態・進捗を併記して更新する
- 次セッションが迷わない情報(判断基準、保留理由、次アクション)を優先して残す
- 今後の検討事項は、本セッションでは対応対象外だが実装・検討の可能性がある項目を記載する
- 作業ログの実施内容は1ファイル1行にまとめ、操作の実況と試行錯誤は記載しない
- 作業ログに作成・修正ファイルの一覧を書かず、成果物セクションへ集約する
- 設計判断サマリは判断時点の追跡に必要なため、分量を理由に省略しない
```
