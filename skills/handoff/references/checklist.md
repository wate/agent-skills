引き継ぎ資料チェックリスト
==========================

引き継ぎ資料を作成する際に、落とし漏れを防ぐためのチェックリストです。
現行テンプレートの12項目に合わせて確認します。

- 参照テンプレート: [../assets/template.md](../assets/template.md)
- 記述例: [examples.md](examples.md)

最小限レベル
-------------------------

短期の作業引き継ぎで、次のセッションが再開判断できる最低限の確認です。

### 目的・背景

- [ ] 目的が1-2文で明確に記載されている
- [ ] 背景に次の判断で使う基準が記載されている

### 未決事項・決定事項・課題とリスク

- [ ] 未決事項が記載されている(なければ「なし」と明記)
- [ ] 決定事項が記載されている(なければ「なし」と明記)
- [ ] 課題またはリスクが記載されている(なければ「なし」と明記)

### タスク一覧

- [ ] 主要タスクのチェックボックスが最新状態になっている
- [ ] 各タスクに状態と進捗が記載されている

### 完了条件・成果物

- [ ] 完了条件が記載されている
- [ ] 成果物に参照先ファイルが列挙されている

標準レベル
-------------------------

複数セッションにまたがる作業で、引き継ぎ品質を安定させる確認です。

### 目的

- [ ] ビジネス価値または期待結果が明確に記載されている

### 背景

- [ ] 経緯だけでなく判断根拠が記載されている

### 未決事項

- [ ] [対応中]/[確認待ち]の状態が明記されている
- [ ] 解決済み項目は未決事項から決定事項へ移管されている

### 決定事項

- [ ] 現時点で有効な決定が記載されている
- [ ] 決定日が記載されている
- [ ] 決定理由が記載されている
- [ ] 影響範囲が記載されている
- [ ] 根拠(参照先)が記載されている
- [ ] 決定更新時は旧決定と変更理由が記載されている

### 課題とリスク

- [ ] 課題とリスクが区別されている
- [ ] リスクに影響度(高/中/低)が記載されている

### タスク一覧

- [ ] タスク順序が維持されている
- [ ] 各タスクに「実施内容」「残り作業」が記載されている
- [ ] 後続タスクを先行着手した場合の理由が記載されている

### 完了条件

- [ ] 完了判定基準が複数項目で記載されている

### 指摘事項

- [ ] 指摘事項と改善方針が記載されている(なければ「なし」と明記)

### 作業ログ

- [ ] セッション単位で記載されている
- [ ] 各セッションに「実施内容」「完了タスク」「設計判断サマリ」がある
- [ ] 実施内容が「`ファイルパス`: 変更内容」の1行形式で記載されている
- [ ] 完了タスクにタスク番号とタスク名が併記されている
- [ ] 作成・修正ファイルの一覧が作業ログへ重複記載されていない

### 成果物

- [ ] 成果物のパスが重複なく整理されている

充実レベル
-------------------------

複数エージェントや長期タスクで、引き継ぎの再現性を高める確認です。

### 未決事項

- [ ] 確認待ち項目に確認先や期限が記載されている
- [ ] 解決後の項目が未決事項に残っていない

### 決定事項

- [ ] 重要な決定に影響範囲が記載されている
- [ ] 更新履歴が追える形で記載されている
- [ ] 未決事項から移管した項目に移管日と決定内容が記載されている
- [ ] 重要な決定に決定理由と根拠(参照先)が記載されている

### 課題とリスク

- [ ] すべての課題とリスクに状態が記載されている
- [ ] 解消済み項目に解消理由が記載されている

### タスク一覧

- [ ] 依存関係やブロック要因がタスク配下で明確化されている
- [ ] 進捗率が全体の実態と矛盾していない

### 作業ログ

- [ ] セッション間の引き継ぎコメントが記載されている
- [ ] 重要な判断は背景・未決事項・決定事項・課題とリスクの該当箇所にも反映されている

### 成果物

- [ ] 参照リンクがすべて有効である
- [ ] 成果物のパスと作業ログの実施内容に現れるファイルが整合している

記載品質
-------------------------

- [ ] セクション名がテンプレートと一致している
- [ ] 用語が統一されている(用語変更時は作業ログに理由を記載)
- [ ] Markdown規約(見出し、インデント、リスト)に準拠している
- [ ] 日本語品質(表記統一、読みやすさ)に問題がない

よくある落とし穴
-------------------------

### 落とし穴1: タスク状態一覧の更新漏れ

症状: 完了済みなのにチェックボックスや進捗が古いまま。

対策: タスク完了時にチェックボックス、状態、進捗、残り作業を同時に更新します。

### 落とし穴2: 未決事項を削除してしまう

症状: 解決済みの経緯が消え、判断理由が追えない。

対策: 解決済みは未決事項から削除し、決定事項へ移管して履歴を残します。

### 落とし穴3: 作業ログが抽象的すぎる

症状: ログを読んでも何をしたか分からない。

対策: 実施内容を「`ファイルパス`: 変更内容」の形式で記載し、どのファイルへ何を加えたかが読み取れる粒度にします。操作の実況や試行錯誤の過程は記載しません。

### 落とし穴4: 成果物リンクの未更新

症状: ファイル名変更後にリンク切れが発生する。

対策: リネーム時は成果物と作業ログの参照先を同時に更新します。

### 落とし穴5: 用語がセッション間で揺れる

症状: 同じ概念を別名で記載し、引き継ぎ先が混乱する。

対策: 用語を固定し、変更が必要な場合は作業ログに変更理由を残します。

### 落とし穴6: 作業ログが肥大化する

症状: セッションごとに成果物と同じファイル一覧が並び、実施内容が操作単位へ分解されて読み通せない。

対策: 作成・修正ファイルの一覧は成果物セクションへ集約し、実施内容は1ファイル1行へまとめます。同種の修正はディレクトリ単位や件数でまとめます。設計判断サマリは判断時点の追跡に必要なため、削減対象に含めません。
