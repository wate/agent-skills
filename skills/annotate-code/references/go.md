Goのアノテーション
=========================

書式
-------------------------

- Goのドキュメントコメントで書き、タグは使わない
- コメントは、宣言の直前に、対象の名前から始める(`// FilterItems は〜`)
- 引数・戻り値・エラーは、必要な場合だけ文の中で説明する
- Goは型を宣言で必ず持つため、コメントで型を補わない

要素ごとの書き方
-------------------------

- 対象: 公開された(大文字で始まる)識別子には、すべてドキュメントコメントを書く。公開されていない識別子は、規約が求める場合だけ書く
- パッケージ: `Package 名前`で始まるコメントを`package`宣言の直前に書く。複数のファイルからなるパッケージでは、1つのファイルにだけ書く
- 非推奨: `Deprecated:`で始まる段落を設け、代わりに使うものを書く

静的解析
-------------------------

- staticcheckの`ST1020`〜`ST1022`は、公開された識別子のコメントが名前から始まるかを検査する(既定では無効)
- `go doc`で、コメントが対象の宣言に付いているかを確かめられる

見本
-------------------------

```go
// FilterItems は、受け取ったリストをキーワードを含む要素だけに絞り込む。
// keyword が空文字の場合は、すべての要素を返す。
func FilterItems(items []string, keyword string) []string {
    var results []string
    for _, item := range items {
        if strings.Contains(item, keyword) {
            results = append(results, item)
        }
    }
    return results
}
```
