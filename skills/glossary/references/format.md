出力パターンの選択
=========================

基本方針
-------------------------

用語集の書式は、既存の用語集がある場合はそれを優先します。
新規に作る場合だけ、定義の長さと項目の数に合わせて3つのパターンから選びます。

既存の用語集がある場合
-------------------------

基本は既存の書式に合わせます。
書式が分類ごとに違う場合や、現行のパターンと食い違う場合は、変換案を差分で示して確認します。

- 出力先の用語集を読み、書式を分類ごとに記録します。
    - 記録する内容: 見出しの文言・順序・階層、記述の形式、列名、用語ごとの項目の並び
- 出力は、記録した書式に合わせます。テンプレートとの一致は求めません。
- 見出しだけで用語の項目がない場合は、新規に作る場合として扱います。
- 新しい用語は、意味の近い分類へ入れます。どの分類にも当てはまらない場合は、新しい分類の追加を提案します。
    - 差分に含める内容: 追加する分類名、置く位置(どの分類の後ろ)、配置する用語、書式
    - 追加する分類の書式は、既存の分類の書式に合わせます。揃っていない場合はユーザーに確認します
- 分類ごとの書式が揃っていない場合は、分類ごとの書式を一覧で示し、どの書式に揃えるかを確認します。
- 記録した書式が現行の3パターンの定義と食い違う場合は、該当の分類について変換案を差分で示します。
    - 食い違いの例: 関連用語の列が全分類に必ずある、パターンにない項目がある、項目の順序が違う
    - 変換案は書式だけを対象にし、用語名と定義の本文は変えません
    - 項目が減る場合は、減る項目とその内容を示します
- 変換は承認を得た分類だけ行います。承認がない分類は既存の書式のまま残します。
- 既存にない項目を足す場合は、既存の項目を残したまま書き込み、書き込み後に差分で確認します。
- 承認を得た範囲を除き、既存の項目を削ったり並べ替えたりしません。

新規に作る場合のパターン
-------------------------

### 表型

- テンプレート: [`assets/glossary_table.md`](../assets/glossary_table.md)
- 形式: 分類ごとの表。基本は用語、定義の2列
- 項目: 定義、関連用語(任意)
- 向くケース: 定義が1行に収まり、用語を並べて見比べたい場合
- 既定のパターン: 迷ったらこれを使います
- 関連用語を書く用語が1つでもある分類だけ、表の右端に`関連用語`の列を足します
- どの用語にも関連用語がない分類では、列を作りません
- 列を足した分類で、関連用語がない用語のセルは`-`にします

定義の幅を優先するため、列は必要になってから足します。
列を足す場合は、次の形にします。

```markdown
| 用語   | 定義         | 関連用語   |
| ------ | ------------ | ---------- |
| 用語名 | (ここに定義) | 関連用語名 |
```

### 一覧型

- テンプレート: [`assets/glossary_list.md`](../assets/glossary_list.md)
- 形式: 用語1件につき箇条書き。括弧に正式名称や読み仮名を添え、定義を続ける
- 項目: 定義、読み仮名、正式名称、関連用語(任意)、補足。多い場合はネストして行を分ける
- 向くケース: 略語に正式名称を添えるため表の列が分けにくい場合。項目が3つ以上ある場合

### 詳細型

- テンプレート: [`assets/glossary.md`](../assets/glossary.md)
- 形式: 用語1件につき見出しと段落
- 項目: 定義、関連用語(任意)、補足
- 向くケース: 定義が2文以上になる、または補足の説明が長くなる場合
- 関連用語がない用語では、関連用語の行を省きます

表型は、表の1行が80桁に収まるときだけ使います。
定義が長くて収まらない場合は、一覧型か詳細型を選びます。

パターンの選び方
-------------------------

1. 依頼で形式や項目の指定があれば、それに合うパターンを選びます。
2. 定義が2文以上になる、または補足が長くなる場合は、詳細型を選びます。
3. 次のいずれかに当てはまる場合は、一覧型を選びます。
    - 略語に正式名称を添える用語がある
    - 補足を書く用語がある
    - 表が80桁に収まらない
4. それ以外は表型を選びます。
5. 選んだパターンと理由をユーザーに示し、承認を得てから出力します。

読み仮名と正式名称の扱い
-------------------------

読み仮名と正式名称は、どのパターンでも必須にしません。
読み方が分かりにくい用語には読み仮名を、略語には正式名称を付けます。

表型には、読み仮名と正式名称を書く欄がありません。
用語の列が広がり、定義の列と分けて読めなくなるためです。
これらを添える用語がある場合は、表型ではなく一覧型を選びます。

### 一覧型

正式名称や読み仮名は括弧に添え、その後に定義を続けます。

```markdown
- API(Application Programming Interface): (ここに定義)
```

次のいずれかに当てはまる場合は、ネストして行を分けます。

- 補足など、括弧に収まらない項目を書く
- 項目が3つ以上ある
- 括弧と定義を並べると1行が80桁を超える

```markdown
- API
    - 正式名称: Application Programming Interface
    - 定義: (ここに定義)
    - 関連用語: (ここに関連用語)
```

不要な用語は、括弧と行を省きます。

### 詳細型

- 読み仮名を付ける用語は、見出しの括弧に書きます。
- 略語は見出しに括弧を付けず、定義の後に正式名称の行を足します。

```markdown
### 棚卸し(たなおろし)
```

```markdown
### API

(ここに定義)

正式名称: Application Programming Interface

関連用語: (ここに関連用語)
```

項目を変える場合
-------------------------

- パターンの項目を減らす場合は、減らす項目をユーザーに示します。
    - 例: 一覧型で補足を書かない
- 関連用語は任意の項目です。該当する用語がない場合は、承認を求めずに列や行を省きます。
- パターンにない項目を足す場合は、一覧型を選び、項目として行を足します。
- パターンにない分類が必要な場合は、分類名と置く位置を示して追加案を作り、承認を得ます。
- どのパターンにも合わない場合は、書式をユーザーと決めます。

検証
-------------------------

- 新規に作る場合、選んだパターンのテンプレートを読み、見出しの文言・順序・階層が一致しているか。
- 新規に作る場合、パターンと項目の対応が、テンプレートの項目と一致しているか。
- 新規に作る場合、選んだパターンと理由をユーザーに示し、承認を得たか。
- 表型を使った場合、表の各行が80桁に収まっているか。
- 表型を使った場合、関連用語の列を、関連用語を書く用語がある分類にだけ足しているか。
- 既存の用語集を扱った場合、書式を分類ごとに記録したか。
- 既存の用語集に用語を足した場合、どの分類にも当てはまらない用語を、新しい分類の追加案にしたか。
- 書式の食い違いを変換した場合、承認を得た分類だけで変換したか。
- 承認を得ずに、既存の用語集の書式を変えていないか。
