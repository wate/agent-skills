ER図(draw.io形式)
=========================

概要
-------------------------

テーブル定義からdraw.io形式の概要ER図を生成する手順を提供します。
非エンジニア(経営層、業務担当者、プロジェクトマネージャー)向けのデータ構造概要図を作る場面を対象にします。
全カラムを網羅する詳細なER図ではなく、主要な関連を俯瞰できることに重点を置きます。

適用場面
-------------------------

- テーブル定義からER図を作成するとき。
- 既存スキーマをリバースエンジニアリングして概要図を作るとき。
- 非エンジニアへの説明資料へER図を組み込むとき。

非適用場面
-------------------------

- 全カラムを網羅する詳細なER図が必要な場合。
- `.d2`形式のER図が必要な場合(`d2`スキルのSQLテーブルを参照)。

生成手順
-------------------------

### 1. 入力形式の判定と解析

受け付ける入力形式は次のとおりです。

- YAML、SQL DDL、Markdown、JSON
- 自然言語による記述
- 既存コード(ORM定義、マイグレーションファイル)
- データベースダンプ、`tbls`の出力

抽出する情報は次のとおりです。

- テーブル名(物理名、論理名)
- 主キー、外部キー
- カーディナリティ(参照元はNOT NULL制約、参照先は明示記載)

### 2. 表示対象カラムの絞り込み

概要図のため、表示するカラムを絞り込みます。

- 表示する: 主キー、外部キー、業務上重要な入力項目
- 表示例: ユーザー名、メールアドレス、商品名、販売価格、ステータス
- 表示しない: タイムスタンプ系(作成日時、更新日時、削除日時)
- 表示しない: システム管理用カラム(バージョン番号、ロック情報)
- カラム名は物理名を使い、日本語化できる場合は日本語表記にします
- カラム一覧は改行区切りにし、キー種別を`(PK)`と`(FK)`で明示します

### 3. カーディナリティの判定

参照元(外部キー側)と参照先(主キー側)を分けて判定します。

- 参照元がNOT NULL: `startArrow=ERone`
- 参照元がNULL許可: `startArrow=ERzeroToOne`
- 参照先が複数: `endArrow=ERzeroToMany`
- 参照先が1つ(1対1): `endArrow=ERzeroToOne`または`endArrow=ERone`
- 1対多の関係: `edgeStyle=entityRelationEdgeStyle`を付与します
- 1対1の関係: `edgeStyle`を付与しません

記法の対応は次のとおりです。

| 記法           | 意味              |
| -------------- | ----------------- |
| `ERzeroToMany` | 0..*(ゼロ以上)    |
| `ERzeroToOne`  | 0..1(ゼロまたは1) |
| `ERone`        | 1(必須)           |
| `ERoneToMany`  | 1..*(1つ以上)     |

### 4. レイアウトと配置

テーブルの役割に応じて配置します。

- マスタ(プロジェクト、ユーザー、ロール、種別、ステータス): 上部・左側
- 中間(メンバー、メンバーロール、カテゴリーとチケットの対応): 中央
- トランザクション(チケット、ジャーナル、添付ファイル): 中央・右側
- 関連(プロフィール、ジャーナル詳細): 主テーブルの近く

配置の基準は次のとおりです。

- 基本グリッド: 10px単位で整列
- テーブル間隔: 水平40-240px、垂直30-170px
- ページサイズ: 幅1169px、高さ827px(A4横向き相当)
- 複数リレーションがある場合は`exitX/exitY`と`entryX/entryY`を調整します

### 5. XML生成

生成する要素は次の3種類です。
基本的なXML構造とスタイル属性は`SKILL.md`を参照してください。

#### テーブル(swimlane)

- `style`は`swimlane;childLayout=stackLayout;horizontal=1;startSize=30`の形式にします
- `value`には論理名(日本語)を指定します
- 高さはカラム数に応じて決めます

#### カラムリスト

- 親テーブルの`id`を`parent`に指定します
- `value`は改行(`&#xa;`)区切りでカラムを列挙します
- `style`は`align=left;strokeColor=none;fillColor=none;spacingLeft=4`の形式にします

#### リレーション(エッジ)

- `source`に参照元、`target`に参照先の`id`を指定します
- スタイルは手順3のカーディナリティ判定に従います

出力
-------------------------

- 出力先: `docs/er_diagram.drawio`(既定値)
- ファイル名: `er_diagram.drawio`で固定
- 呼び出し元の指示がある場合は、その出力先を優先します
- 50テーブルを超える場合は主要テーブルに限定します

図種固有の制約・禁止事項
-------------------------

- 概要図として主要項目のみを表示します(全カラムの網羅は対象外)
- 入力に存在する外部キー関係はすべて矢印で表現します(漏れは禁止)
- カーディナリティは参照元と参照先を区別して表現します
- テーブル名は論理名のみを表示します(物理名の併記は禁止)
- カラム名へ装飾アイコンを付けません
- 命名規則からも判断できない外部キーを推測で追加しません
- サンプルと異なるスタイル定義を使用しません

図種固有のエラー対応
-------------------------

- 入力形式を判定できない: ユーザーへ入力形式の指定を求めます
- 外部キーの抽出に失敗: 推測ロジックの適用可否をユーザーへ確認します
- 参照先のカーディナリティが不明: `ERzeroToMany`を既定とし、その旨を明示します
