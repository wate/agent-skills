D2言語図表ファイル操作
=========================

概要
-------------------------

D2言語形式の図表ファイルの作成・読み取り・編集をプログラマティックに行うためのスキルです。
新規図表の生成、既存図表の読み込みと解析、テキストベースで記述でき、Gitでの差分追跡が容易な図表操作手順を提供します。

### 適用場面

- システムフロー図やデータフロー図の作成
- 既存D2ファイルの読み込みとノード・エッジ情報の抽出
- シーケンス図や状態遷移図の生成
- アーキテクチャ図やコンポーネント関連図の作成
- Git管理下で差分追跡したい図表
- コードレビュー対象としたい設計図
- 図表の構文解析とバリデーション

### 非適用場面

以下の場合は本スキルを適用しません。

- draw.io形式の図表作成・編集依頼(`drawio`スキルを使用)
- Mermaid形式の図表作成依頼(Mermaid描画機能を使用)
- 図表のレビューのみで、D2ファイルの作成・編集を伴わない依頼

### drawioとの使い分け

出力形式は、依頼されたファイル形式で決まります。

- `.d2`ファイルの作成・編集を求められた場合は本スキル
- `.drawio`ファイルの作成・編集を求められた場合は`drawio`スキル
- 作成後にGUIで配置を手直しする前提の図は`drawio`スキル
    - PNG、SVG、PDFは本スキルでも`d2`コマンドで出力できるため、画像が必要なことだけでは`drawio`スキルを選びません
- 形式の指定がない場合は、図の読み手で判断します
    - AIやツールがテキストとして読む図は本スキル(設計の記述、Gitでの差分確認、後続の自動処理)
    - 人間が図として見る図は`drawio`スキル(クライアントへの提示、資料への添付)
- 読み手も判断できない場合は、推測せずユーザーへ確認します

前提条件
-------------------------

### 必要な環境・ツール

- D2コマンドラインツール(TALAを使う場合はv0.9.0以降)
- テキストエディタ
- 画像変換が必要な場合は出力先ディレクトリへの書き込み権限

#### macOS

```bash

brew install d2

# バージョン確認

```

#### Linux

```bash

curl -fsSL https://d2lang.com/install.sh | sh -s --

# 手動インストール(Go環境がある場合)
go install oss.terrastruct.com/d2@latest
```

仕様
-------------------------

### 基本的な構造

D2ファイルの基本構造は以下の通りです。

```d2
# 図表タイトル
# =========================

vars: {
  d2-config: {
    layout-engine: dagre     # dagre (デフォルト) / elk / tala
    theme-id: 0              # テーマIDを指定
  }
}

# ノード定義
node1: ラベル1
node2: ラベル2

# エッジ定義
node1 -> node2: 接続ラベル
```

#### 主要な要素

- ノード: 図表上の要素(四角形、円、菱形など)
- エッジ: ノード間の接続線と関係性
- コンテナ: 関連するノードをグループ化
- スタイル: 色、形、レイアウトなどの見た目制御
- shape: ノードの図形タイプを指定

#### 次のステップ

詳細な構文や高度な使い方については、以下を参照してください。

- [テンプレートファイル](#テンプレートファイル) - すぐに使えるテンプレート

### D2ファイル構造の基本

#### 推奨されるファイル構造

```d2
# {図表タイトル}
# =========================
# 業務プロセス: {プロセス名}

## レイアウトエンジンとテーマの定義
## -------------------------
vars: {
  d2-config: {
    layout-engine: dagre
    theme-id: 0
  }
}

## ノード定義
## -------------------------
# ここにノード定義

## エッジ定義
## -------------------------
# ここにエッジ定義

## スタイル定義
## -------------------------
# グローバルなスタイルのみを冒頭に置くことを推奨
# 詳細なスタイルは末尾にまとめる
style: {
  # ここにグローバルstyle定義
}

classes: {
  # ここにclasses定義
}
```

#### 外部ファイルの読み込みと共通スタイル化

D2は`@file`と`...@file`による外部`.d2`ファイルの読み込みに対応しています。
共通の`classes`や接続スタイル、`globs`を別ファイルに切り出し、個別の図では参照だけを書く構成を推奨します。

```d2
# common_styles.d2
status_complete: {
  shape: circle
  style: {
    fill: white
    stroke: blue
    font-color: blue
  }
}

# task_status.d2
classes: {
  ## ステータス：完了
  status_complete: @common_styles.status_complete
}
```

- `@common_styles.status_complete`: 外部ファイルの特定オブジェクトを読み込みます。
- `...@common_styles`: mapの中へまとめて展開します。
- 相対パスは読み込むファイル基準です。
- `.d2`拡張子は省略できます。
- コメントは見やすさのために参照側にも残して構いません。
- importをまたいで共通の`glob`を効かせたい場合は、通常の`*`/`**`ではなく`***`を検討します。

#### レイアウトエンジンの選択指針

| レイアウトエンジン | 適した図表タイプ                             | 特徴                                                                      |
| ------------------ | -------------------------------------------- | ------------------------------------------------------------------------- |
| `dagre`            | フロー図、依存関係図、シーケンス図           | デフォルト。有向グラフを見やすく配置、汎用的な用途向け                    |
| `elk`              | 階層構造、ツリー図、システム構成図           | ノードを階層的に配置、大規模図表に適している                              |
| `tala`             | アーキテクチャ図、構成図、位置を固定したい図 | 直交配置。`top`/`left`による座標固定、コンテナ単位の`direction`指定に対応 |

TALAはD2 v0.9.0以降に本体へ同梱され、D2と同じライセンス(MPL-2.0)で利用できます。
利用可否は`d2 layout`の出力(`tala (bundled)`と表示されるか)で確認してください。
トレードオフを含む詳細は[レイアウトエンジン](references/layouts.md)を参照してください。

| 要素種別          | 塗りつぶし色 | 線色    | 用途                            |
| ----------------- | ------------ | ------- | ------------------------------- |
| フロントエンド    | #e3f2fd      | #1976d2 | UI、クライアント側処理          |
| バックエンド      | #e8f5e8      | #388e3c | サーバー、API、ビジネスロジック |
| データ層          | #fff3e0      | #f57c00 | データベース、ストレージ        |
| 外部システム      | #fce4ec      | #c2185b | 外部API、サードパーティサービス |
| ユーザー/アクター | #add8e6      | #0000ff | 人物、ユーザーロール            |
| 重要な処理        | #ffebee      | #c62828 | エラー処理、重要な判断処理      |

作成手順
-------------------------

図を新しく作る場合は、次の順で進めます。

1. 図種を決め、「テンプレートファイル」節から対応するテンプレート(`assets/`)を特定します
    - 図種別の生成手順がある場合(`references/`のフローチャート、アクティビティ図、画面遷移図、シーケンス図)は、それも読み込みます
2. 出力する前に、テンプレートを開いて読み込みます
3. テンプレートの構成に合わせて書きます
    - 節のコメント(`## ノード定義`等)がある場合は、その順序を変えません
    - `classes`はテンプレートの定義を使い、記憶にもとづいて書き換えません
    - 仕様にある要素と関係だけを書きます
4. 出力後、`d2 validate <ファイル>`で構文を検証します
    - 終了コードが0以外の場合は、表示された行を直して再検証します
    - `d2`コマンドが使えない環境では、未検証である旨を依頼者へ伝えて終えます

「テンプレートファイル」節の説明は索引であり、テンプレートの代わりにはなりません。

トラブルシューティング
-------------------------

### 基本的な確認項目

- d2コマンドが見つからない: インストール状況とPATHを確認
- レイアウトが崩れる: layout-engineの選択、コンテナ構造、direction指定を見直す
- 日本語が表示されない: UTF-8、font-family、日本語フォントの有無を確認
- 画像が生成されない: 構文エラーと出力先権限を確認
- エッジが交差する: レイアウトの再検討、ノード順序の調整、図の分割を検討

技術的制約と禁止事項
-------------------------

### サイズと位置の指定

ノードのサイズや配置は、レイアウトエンジン(dagre、ELK、TALA)に任せます。
手で指定するとレイアウトが崩れやすいため、次の方針で扱います。

- `width`、`height`: 原則として使いません
    - 画像や`sql_table`など大きさをそろえる必要がある場合だけ、[寸法設定](references/dimensions.md)の制約に従って使います
- `near`: 図のタイトルや凡例を定位置(`top-center`等)に置く用途だけに使います
    - フローを構成するノードには使いません。使い方は[位置設定](references/positions.md)を参照してください
- `top`、`left`: TALAで座標を固定する場合だけ使います([位置設定](references/positions.md)を参照)
- `x`、`y`、`position`、`size`: D2の予約語ではないため使いません
    - エラーにはならず、値をラベルにした子ノードとして描画されます(例: `x: 10`は「10」という子ノードになります)

### 構文制約

- 単一行コメント(`#`)のみ使用、ブロックコメント禁止
- 抽象化レベル統一(詳細度の混在禁止)

### 品質制約

- 論理的整合性: フローの循環参照(無限ループ)作成禁止、すべてのフローに明確な終了条件必須
- 視覚的明瞭性: 過度な複雑化による理解困難回避、装飾目的の余分な要素追加禁止
- 整合性: 提供された仕様に存在しない要素や関係の追加禁止
