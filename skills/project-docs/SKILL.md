project-docs
=========================

概要
-------------------------

プロジェクトの基準となる次の3文書を作成・更新します。

- `technology.md`: 技術スタック
- `directory_structure.md`: ディレクトリ構造
- `code_style.md`: コーディング規約

設定ファイルとディレクトリを事実の起点とし、推測で補いません。
対象文書は、依頼で指定されたものだけを更新します。
新規作成と既存更新の両方に対応し、既存更新では差分確認を挟みます。

前提条件
-------------------------

- リポジトリのルートで実行します。
- 設定ファイルとディレクトリの読み取り権限があります。
- 出力先のディレクトリを作成できる権限があります。
- 既存文書を更新する場合は、差分を確認できる状態にします。

仕様
-------------------------

### 対象文書

| 文書                     | 内容                                                                             | 主な入力                                                       |
| ------------------------ | -------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| `technology.md`          | 言語・フレームワーク、データベース、実行環境、依存パッケージ、バージョン管理方針 | `composer.json`・`package.json`・`Gemfile`・`pyproject.toml`等 |
| `directory_structure.md` | ディレクトリツリー、主要ディレクトリ・ファイルの役割                             | ディレクトリ構成、設定ファイル                                 |
| `code_style.md`          | 改行・インデント、言語別規約、Linter設定                                         | EditorConfig・Markdownlint・PHP・Prettier・ESLint等            |

この表は索引であり、テンプレートの代用ではありません。

### カスタマイズ

- 出力先は依頼で指定できます。
- 3階層で出力するパスは、依頼で指定できます。
- バージョン管理方針は、既存文書とユーザーの判断を優先します。

### 出力先

- ユーザーが出力先を指定した場合は、そのディレクトリを使います。
- 指定がない場合は`docs/`へ出力します。
- 出力先のディレクトリがない場合は作成します。
- 複数文書を一度に作る場合も、文書ごとに出力先を確認します。

### 既存文書の扱い

1. 出力先に同名ファイルがある場合は、既存内容を読みます。
2. 生成案と既存内容の差分を示します。
3. ユーザーの承認を得てから更新します。
4. 承認がない場合は上書きしません。

### テンプレート

出力形式は次のテンプレートを正本とします。
出力前に必ず読み込み、見出しの文言・順序・階層を一致させます。

- `technology.md`: [assets/technology.md](assets/technology.md)
- `directory_structure.md`: [assets/directory_structure.md](assets/directory_structure.md)
- `code_style.md`: [assets/code_style.md](assets/code_style.md)

見出しの追加・削除・順序変更・記憶による書き換えはしません。
題名(見出し1)と、その下の説明の文も必ず書きます。`[プロジェクト名]`のようなプレースホルダーだけを置き換えます。
`assets/`はテンプレートであり、出力先ではありません。

手順
-------------------------

1. 依頼から対象文書を決めます。指定がなければ、3文書すべてを候補にします。
2. 対象文書に応じて、設定ファイルとディレクトリを読みます。
3. 対象文書の`references/`と`assets/`を読みます。
4. 事実だけを使って生成案を作ります。
5. 既存文書がある場合は差分を示し、承認を得ます。
6. 承認後に出力先へ書き、見出しをテンプレートと突き合わせます。
    - 書いたファイルの先頭が題名(見出し1)で始まり、その下に説明の文があることを確かめます。ない場合は書き足します。
7. 変更した文書と、確認できなかった点を報告します。

制約
-------------------------

- 設定ファイルに書かれていないルールや技術を追加しません。
- 推測した値は「要確認」と書き、根拠を添えます。
- 機密情報(認証情報、APIキー、秘密鍵)を書きません。
- デプロイ環境の情報は`technology.md`の対象外です。
- ディレクトリ構造は既定2階層です。3階層にするパスは、ユーザーが指定したものだけです。
- 役割宣言や、他のスキル・プロンプトの名前を書きません。

トラブルシューティング
-------------------------

- 設定ファイルがない: そのセクションを省略し、確認できなかった旨を報告します。
- バージョンが不明:「要確認」と書き、根拠のファイルを示します。
- 既存文書が手で編集されている: 差分を示し、残す記述を確認します。承認なしに上書きしません。
- 出力先に書き込めない: 別の出力先をユーザーへ確認します。

参照ファイル
-------------------------

- `references/technology.md`: 技術スタックの収集・分類・バージョン管理方針
- `references/directory-structure.md`: ディレクトリ構造の出力規則・例外・順序
- `references/code-style.md`: Linter設定の収集・言語別規約への統合
