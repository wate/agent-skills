ポリシーの監査
=========================

基本方針
-------------------------

監査は、ポリシーの基準をコード・設定・CIに突き合わせる作業です。
方針とガイドラインは検証しないため、監査の対象外とします。

機械的に確かめられない基準は、違反と断定せず「手段未定義」として報告します。

基準の抽出
-------------------------

1. 対象のポリシー文書を読み、h2の「基準」配下の記述を1項目ずつ取り出します。
2. 表やチェックリストは、行または項目を1つの基準として扱います。ただし、評価の尺度、重要度の区分、目安の段階、検証範囲の説明のように定義を並べた表は、表全体を1つの基準として扱います。
3. 「方針」配下の記述と、基準の中にある推奨のやり方の記述は、対象外として1項目ずつ取り出します。方針はh3の見出しごとに1件として数えます。
4. 抽出した件数を数え、報告の集計と一致することを確かめます。

根拠の収集
-------------------------

種別ごとの内容は、`references/`の種別ファイル(例: テストポリシーは`test-policy.md`)を読みます。
種別ファイルがない種別(汎用テンプレートで作ったポリシー)は、`references/collection.md`の事実の起点だけを探します。
根拠が見つからない基準は「手段未定義」とします。

結果の分類
-------------------------

結果は次の4つだけを使います。

| 分類       | 意味                                               | 出力                                   |
| ---------- | -------------------------------------------------- | -------------------------------------- |
| 一致       | 基準と根拠が合っている                             | 根拠のファイルと箇所を示す             |
| 乖離       | 基準と根拠が食い違っている                         | 差分と修正案を示す                     |
| 手段未定義 | 基準を確かめる設定や仕組みが見つからない           | 違反と断定せず、不足している手段を示す |
| 対象外     | 方針、またはガイドライン(推奨のやり方)の記述である | 検証しない                             |

### 分類の判断

- 根拠が見つかり、基準を満たしている場合は「一致」とします。
- 根拠が見つかり、基準を満たしていない場合は「乖離」とします。
- 基準を確かめる仕組み(設定やテストコード)があり、基準を満たしていない場合は「乖離」とします。確かめるべきケースのテストが足りない場合も「乖離」です。
- 根拠が見つからない場合は「手段未定義」とします。値の大小は問いません。
- 方針の記述と、ガイドライン(推奨のやり方)の記述は「対象外」とします。

ガイドラインから外れても違反としないため、「乖離」として扱いません。

「72時間以内」のような期限や、「重要度に応じて判断する」のような人手の判断は、機械的に確かめられません。
これらは「手段未定義」として報告し、違反として扱いません。

出力
-------------------------

監査の報告は、次の形式で1つのMarkdownファイルにまとめます。

```
# 監査報告 - {ポリシー名}

## 対象

- 文書: {ポリシーのパス}
- 監査日: {日付}
- 根拠として読んだファイル: {一覧}

## 結果

| #   | 基準         | 分類       | 根拠           | 提案         |
| --- | ------------ | ---------- | -------------- | ------------ |
| 1   | {基準の要約} | 一致       | {ファイルと箇所} | なし         |
| 2   | {基準の要約} | 乖離       | {ファイルと箇所} | {修正案}     |
| 3   | {基準の要約} | 手段未定義 | なし           | {必要な手段} |
| 4   | {方針の要約} | 対象外     | なし           | なし         |

## 集計

| 分類       | 件数 |
| ---------- | ---- |
| 一致       | 0    |
| 乖離       | 0    |
| 手段未定義 | 0    |
| 対象外     | 0    |
| 合計       | 0    |

## 読み取り

{乖離の要約と、手段未定義の主な原因}
```

### 出力の制約

- 結果の表の行数は、抽出した基準と方針の件数の合計と一致させます。
- 集計の合計は、結果の表の行数と一致させます。
- 分類は4つ以外の語を使いません。
- 根拠が見つからない基準を、根拠なしで「一致」や「乖離」にしません。
- 修正案は、基準を変える案と手段を足す案を区別して書きます。

制約
-------------------------

- チケットや課題管理の記録を根拠にしません。予定や経緯の記録であり、基準を満たしている証拠にならないためです。
- 方針とガイドラインの妥当性を評価しません。
- 監査の結果を理由に、ポリシーやコードを書き換えません。修正はユーザーの承認後に別の作業として行います。
- 根拠を読めなかった場合は、その旨を報告に書き、推測で分類しません。
