ポリシーの収集とプロファイル
============================

基本方針
-------------------------

事実の起点から読み取れる内容だけで、方針と基準を組み立てます。
読み取れない項目は推測で埋めず、ユーザーに確認するか「要確認」と明記します。

文書の種類
-------------------------

ポリシーかどうかは、記述が方針と基準で構成されているかで判定します。

- ポリシー: 方針+基準(+手段の概要)。拘束力がある
- ガイドライン: 基準を満たすための推奨のやり方。拘束力はなく、外れる場合は理由を示す
- 運用ルール: 基準+手順(方針を持たない)。拘束力がある
- 手順書: 手順のみ

方針を持たない文書(ガイドライン・運用ルール・手順書)は、生成対象と監査対象から外します。
実装方針のような推奨のやり方はガイドラインに置き、ポリシーの基準に含めません。

事実の起点
-------------------------

次の順に読み、ポリシーに関係する事実だけを拾います。

### プロジェクトの基準文書

- プロジェクトブリーフ
- 技術スタック
- ディレクトリ構造
- コーディング規約

### 設定ファイル

- パッケージ定義: `composer.json`、`package.json`、`Gemfile`、`pyproject.toml`、`Pipfile`
- テスト設定: `phpunit.xml`、`phpunit.xml.dist`、`jest.config.*`、`vitest.config.*`、`playwright.config.*`、`cypress.config.*`、`pytest.ini`、`pyproject.toml`
- 静的解析設定: `phpcs.xml`、`phpstan.neon`、`psalm.xml`、`.eslintrc*`、`eslint.config.*`、`.rubocop.yml`
- カバレッジ設定: テスト設定ファイル内のカバレッジ指定、`.nycrc*`、`codecov.yml`

### CI設定

- `.github/workflows/`配下のワークフロー定義
- `.gitlab-ci.yml`、`Jenkinsfile`、`azure-pipelines.yml`、`.circleci/config.yml`

### 既存文書

- 出力先にある既存のポリシー文書
- ポリシーから参照される手順書

### 収集の制約

- チケットや課題管理の記録は根拠に含めません。予定や経緯の記録であり、基準を満たしている証拠にならないためです。
- 設定ファイルに書かれていない仕組みを、あるものとして扱いません。
- 実行結果がない基準は、値の有無にかかわらず「要確認」とします。

プロファイル項目
-------------------------

プロファイルは事実の起点から読み取り、足りない項目だけをユーザーに確認します。
各項目がポリシーのどこへ効くかは、次のとおりです。

| 項目         | 効く先     | 読み取る事実                             |
| ------------ | ---------- | ---------------------------------------- |
| 公開範囲     | 方針       | 公開先、利用者の範囲、認証の要否         |
| 扱うデータ   | 方針・基準 | 個人情報、決済情報、機密情報の有無       |
| 規制         | 基準       | 適用される法令、監査、記録保持の要件     |
| 体制         | 手段の概要 | 開発人数、テストを書く担当、自動化の経験 |
| リリース頻度 | 方針・基準 | デプロイの頻度、リリース判定の方法       |

体制は手順の実現可否に効くため、ポリシー本文ではなく手段の概要の判断に使います。

### 扱うデータの確認

事実の起点からデータの種別が読み取れない場合に、次を確認します。

- 個人情報を扱う場合、どの項目が個人情報に当たりますか。
- 決済情報を扱う場合、自社で保持しますか、外部のサービスに委ねますか。
- 業務上の機密情報を扱う場合、どの情報が該当しますか。

### 規制の確認

事実の起点から適用条件が読み取れない場合に、次を確認します。

- 適用される法令や業界のルールはありますか。
- 監査や記録の保持を求める要件がある場合、対象と保持期間を教えてください。
- 外部への報告義務がある場合、対象と期限を教えてください。

テンプレート変数
-------------------------

種別ごとの内容は、`references/`の種別ファイル(例: テストポリシーは`test-policy.md`)を読みます。

値の決め方
-------------------------

- 既存のポリシー文書に値がある場合は、その値を引き継ぎます。
- CI設定やテスト設定に値がある場合は、設定値を事実として扱います。
- どちらにもない場合は目安を使い、ユーザーに確認したうえで確定します。
- 確認が得られない場合は「要確認」と書き、根拠にしたファイルを示します。
