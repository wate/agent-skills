テストポリシーの収集と監査
==========================

テストポリシー専用の内容をまとめます。
テンプレート変数と、基準の種類ごとの根拠の探し方を扱います。

テンプレート変数
-------------------------

テンプレートは基準値を変数として持ちます。
生成時はプロファイルと既存文書から値を決め、変数を残したまま出力しません。

| 変数                               | 意味                                   | 目安                       |
| ---------------------------------- | -------------------------------------- | -------------------------- |
| `{プロジェクト名}`                 | ポリシーの対象プロジェクト名           | プロジェクトブリーフの名称 |
| `{ユニットテストカバレッジ目標}`   | 良好とみなすカバレッジ率               | 70%                        |
| `{カバレッジ改善余地}`             | 改善余地があるとみなす下限             | 50%                        |
| `{自動テスト成功率}`               | リリース判定で求める成功率             | 95%                        |
| `{対応ブラウザ}`                   | 動作確認の対象となるブラウザ           | 主要ブラウザ               |
| `{テスト設計手順書}`               | テスト設計の手順書のパス               | 出力先の手順書の置き場所   |
| `{ユニットテスト手順書}`           | ユニットテストの手順書のパス           | 出力先の手順書の置き場所   |
| `{インテグレーションテスト手順書}` | インテグレーションテストの手順書のパス | 出力先の手順書の置き場所   |
| `{E2Eテスト手順書}`                | E2Eテストの手順書のパス                | 出力先の手順書の置き場所   |
| `{ユーザビリティテスト手順書}`     | ユーザビリティテストの手順書のパス     | 出力先の手順書の置き場所   |

数値の目安は一般的な出発点です。
既存文書やCI設定に値がある場合は、そちらを優先します。

根拠の収集
-------------------------

基準の種類ごとに、次の場所を探します。

### テスト設計の基準

- テスト設計の手順書
- テストパターンの一覧と実装有無の記録
- テストコードの有無

### 品質基準

- CI設定のテスト実行ジョブ
- テストレポートとカバレッジレポート
- リリース手順の定義

### ユニットテストの基準

- テスト設定のカバレッジ指定
- CIのカバレッジ計測とレポート出力
- カバレッジのしきい値設定

### インテグレーションテストの基準

- テストコードとルーティング定義
- 認証・認可の設定
- CIのテスト実行ジョブ

### E2Eテストの基準

- E2Eテストの設定ファイル
- E2Eテストコード
- CIのE2E実行ジョブとレポート

### ユーザビリティテストの基準

- 評価記録と評価シート
- ペルソナ定義
- 改善の記録

### テストデータの基準

- Fixture・seed・テストデータファイル
- テストコード内のデータ準備と後始末
- テスト間のデータ分離の実装
