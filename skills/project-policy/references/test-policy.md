テストポリシーの収集と監査
==========================

テストポリシー専用の内容をまとめます。
テンプレート変数と、基準の種類ごとの根拠の探し方を扱います。

テンプレート変数
-------------------------

テンプレートは基準値を変数として持ちます。
生成時はプロファイルと既存文書から値を決め、変数を残したまま出力しません。

| 変数                             | 意味                                     | 目安                          |
| -------------------------------- | ---------------------------------------- | ----------------------------- |
| `{プロジェクト名}`               | ポリシーの対象プロジェクト名             | プロジェクトブリーフの名称    |
| `{ユニットテストカバレッジ目標}` | 良好とみなすカバレッジ率                 | 70%                           |
| `{カバレッジ改善余地}`           | 改善余地があるとみなす下限               | 50%                           |
| `{自動テスト成功率}`             | リリース判定で求める成功率               | 95%                           |
| `{対応ブラウザ}`                 | 動作確認の対象となるブラウザ             | 主要ブラウザ                  |
| `{テストガイドライン}`           | テストの進め方を書いたガイドラインのパス | `docs/guideline/testing/`配下 |

数値の目安は、中規模を想定した一般的な出発点です。
小規模では、実績がない値を「要確認」として利用者と決めます。
ガイドラインのパスの目安は、ガイドラインの既定の置き場所`docs/guideline/{領域}/`に合わせています。
既存文書やCI設定に値がある場合は、そちらを優先します。

節の適用条件
-------------------------

テンプレートの節は、すべてを毎回出しません。
プロファイルの規模と体制から、適用条件を満たす節だけを使います。
満たさない節は、見出しごと落とします。

### 必須の節

- 方針: テスト戦略、テスト設計の考え方、品質の考え方
- 基準: テスト設計の基準、品質基準、ユニットテストの基準
- 手段の概要: テスト設計

### 条件付きの節

- インテグレーションテスト
    - 適用条件: 複数の層をまたぐ処理がある
    - 満たさない場合: 節と、手段の概要の対応する行を落とす
- E2Eテスト
    - 適用条件: ブラウザで操作する画面がある
    - 満たさない場合: 節と、手段の概要の対応する行を落とす
- ユーザビリティテスト
    - 適用条件: 利用者を集めた評価を回す体制がある
    - 満たさない場合: 節と、手段の概要の対応する行を落とす
- テストデータ
    - 適用条件: テストでデータベースや外部データを使う
    - 満たさない場合: 節を落とす

利用者を集めた評価を回す体制は、開発人数と利用者の範囲から判断します。
個人開発や、利用者が開発者本人だけの場合は満たしません。

落とした節は、理由の根拠にした事実とあわせて報告します。
落とした節を、規模が変わった後の見直し候補として報告します。

根拠の収集
-------------------------

基準の種類ごとに、次の場所を探します。

### テスト設計の基準

- テストのガイドライン
- テストパターンの一覧と実装有無の記録
- テストコードの有無

### 品質基準

- CI設定のテスト実行ジョブ
- テストレポートとカバレッジレポート
- リリース手順の定義

### ユニットテストの基準

- テスト設定のカバレッジ指定
- CIのカバレッジ計測とレポート出力
- カバレッジのしきい値設定

### インテグレーションテストの基準

- テストコードとルーティング定義
- 認証・認可の設定
- CIのテスト実行ジョブ

### E2Eテストの基準

- E2Eテストの設定ファイル
- E2Eテストコード
- CIのE2E実行ジョブとレポート

### ユーザビリティテストの基準

- 評価記録と評価シート
- ペルソナ定義
- 改善の記録

### テストデータの基準

- Fixture・seed・テストデータファイル
- テストコード内のデータ準備と後始末
- テスト間のデータ分離の実装
