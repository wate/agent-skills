project-policy
=========================

概要
-------------------------

`docs/`直下のポリシーを、方針と基準で構成して生成します。
生成したポリシーの基準が、コード・設定・CIと合っているかを監査します。

ポリシーは「方針」と「基準」の2要素で構成します。
基準を満たすための手順は手段の概要にとどめ、詳細は手順書へ置きます。

前提条件
-------------------------

- リポジトリのルートで実行します。
- 設定ファイル・CI設定・既存文書の読み取り権限があります。
- 出力先のディレクトリを作成できる権限があります。
- 既存のポリシーを更新する場合は、差分を確認できる状態にします。

仕様
-------------------------

### 対象文書

| 文書                                 | テンプレート                |
| ------------------------------------ | --------------------------- |
| テストポリシー                       | `assets/test_policy.md`     |
| セキュリティポリシー                 | `assets/security_policy.md` |
| AI利用ポリシー                       | `assets/ai_policy.md`       |
| 種別固有のテンプレートがないポリシー | `assets/policy.md`          |

この表はテンプレートの索引であり、テンプレートの代用ではありません。
新規ポリシーの種別と論点は、[references/policy-catalog.md](references/policy-catalog.md)を参照します。
カタログにない種別でも汎用テンプレートで草案作成を続け、種別固有の不明点は「要確認」とします。

### 文書の種類

ポリシーかどうかは、記述が方針と基準で構成されているかで判定します。

- ポリシー: 方針+基準(+手段の概要)。拘束力がある
- ガイドライン: 基準を満たすための推奨のやり方。拘束力はなく、外れる場合は理由を示す
- 運用ルール: 基準+手順(方針を持たない)。拘束力がある
- 手順書: 手順のみ

方針を持たない文書は、生成対象と監査対象から外します。

### 出力先

- ユーザーが出力先を指定した場合は、そのディレクトリを使います。
- 指定がない場合は`docs/`へ出力します。
- ファイル名は、出力先の既存ファイルの命名規則に合わせます。
- 出力先に同名ファイルがある場合は、差分を示して承認を得てから更新します。

### テンプレート

出力形式は、次のテンプレートを正本とします。
出力前に必ず読み込み、見出しの文言・順序・階層を一致させます。

- テストポリシー: [assets/test_policy.md](assets/test_policy.md)
- セキュリティポリシー: [assets/security_policy.md](assets/security_policy.md)
- AI利用ポリシー: [assets/ai_policy.md](assets/ai_policy.md)
- 種別固有のテンプレートがないポリシー: [assets/policy.md](assets/policy.md)

見出しの追加・削除・順序変更・記憶による書き換えはしません。
`{}`で囲んだ変数だけを、プロファイルと既存文書から決めた値に置き換えます。
変数を残したまま出力しません。
`assets/`はテンプレートであり、出力先ではありません。

### 生成モード

1. プロファイルを確定します。公開範囲、扱うデータ、規制、体制、リリース頻度を、事実の起点から読み取ります。
2. 必要な文書を決めます。
3. 方針を決めます。選択肢と影響を示し、ユーザーの判断を求めます。
4. 方針を満たす基準を決めます。基準値は変数として提示し、値を確認します。
5. 基準を満たす手段の概要を1〜3項目添えます。手順書は変数で参照します。
6. 文書間の参照関係を整合させます。
7. 差分を提示し、承認を得てから書き込みます。

### 新規ポリシーの生成

1. [references/collection.md](references/collection.md)からプロファイルを確定し、[references/policy-catalog.md](references/policy-catalog.md)を読んで必要な種別を判定します。
2. カタログにある種別の論点を提示します。カタログにない種別は、種別固有の論点を確認し、不明点を「要確認」とします。
3. 方針の選択肢と影響を示し、ユーザーと方針を決めます。
4. 方針を満たす基準を設定します。判断材料が不足する値は推測せず「要確認」とします。
5. 基準を満たす手段の概要を1〜3項目添えます。
6. 既存ポリシーの節に置くか独立した文書にするかを決め、出力先と種別に応じたファイル名を確認します。

テンプレートは種別固有のものがあればそれを使い、なければ汎用テンプレートを使います。
汎用テンプレートのファイル名を出力ファイル名には使いません。
差分を提示して承認を得るまで、出力先へ書き込みません。

### 監査モード

1. 基準を抽出します。
2. コード・設定・CIから根拠を収集します。
3. 基準ごとに結果を分類します。
4. 分類ごとの出力を報告にまとめます。

分類は「一致」「乖離」「手段未定義」「対象外」の4つです。
方針とガイドラインは検証せず、対象外とします。

手順
-------------------------

1. 依頼から、生成か監査かを決めます。
    - 判断できない場合は、ユーザーに確認して停止します。
2. 対象のポリシーと出力先を決めます。
3. [references/collection.md](references/collection.md)を読みます。
4. 事実の起点を読み、プロファイルを確定します。
5. 生成モードでは`assets/`のテンプレートを、監査モードでは[references/audit.md](references/audit.md)を読みます。
    - あわせて、対象の種別ファイル(例: テストポリシーは`references/test-policy.md`)も読みます。
    - 新規生成では[references/policy-catalog.md](references/policy-catalog.md)も読み、種別固有のテンプレートがない場合は汎用テンプレートを使います。
6. 生成モードでは、方針と基準を組み立て、差分を提示して承認を得ます。
7. 監査モードでは、基準を抽出し、根拠を収集して分類します。
8. 出力後、見出しをテンプレートと突き合わせます。
    - 書いたファイルの先頭が題名(見出し1)で始まり、その下に説明の文があることを確かめます。ない場合は書き足します。
    - 変数を置き換えた行以外の文言が、テンプレートと一致していることを確かめます。
9. 変更した文書と、確認できなかった点を報告します。

制約
-------------------------

- 設定ファイル・CI設定・既存文書にない仕組みを、あるものとして扱いません。
- 推測した値は「要確認」と書き、根拠を添えます。
- 機械検証できない基準を「違反」と断定しません。
- 方針とガイドラインの妥当性を評価しません。
- 手順の詳細をポリシーに書きません。コマンド・画面操作・作業順序は手順書へ置きます。
- チェックボックスや記入欄を置きません。基準は、満たすべき水準として書きます。
- 実装方針のような推奨のやり方は、ポリシーの基準に入れません。
- チケットや課題管理の記録を、根拠にしません。
- 機密情報(認証情報、APIキー、秘密鍵)を書きません。

トラブルシューティング
-------------------------

- 設定ファイルがない: その基準は「手段未定義」として報告し、根拠にしたファイルがない旨を書きます。
- プロファイルが読み取れない: 推測せず、ユーザーに確認します。確認が得られない場合は「要確認」と書きます。
- 既存文書が手で編集されている: 差分を示し、残す記述を確認します。承認なしに上書きしません。
- 出力先に書き込めない: 別の出力先をユーザーへ確認します。
- カタログにない種別を依頼された: 汎用テンプレートで草案作成を続け、種別固有の不明点は「要確認」とします。

-------------------------

- `references/audit.md`: 基準の抽出、4分類、報告の形式
- `references/test-policy.md`: テストポリシーのテンプレート変数と、基準の種類ごとの根拠の収集先
- `references/security-policy.md`: セキュリティポリシーのテンプレート変数と、基準の種類ごとの根拠の収集先
- `references/ai-policy.md`: AI利用ポリシーのテンプレート変数と、基準の種類ごとの根拠の収集先
- `references/policy-catalog.md`: 新規ポリシーの種別、論点、必要になる条件、既定の置き場所
- `references/policy-type-addition.md`: 種別をカタログへ登録するときだけ読む追加手順
